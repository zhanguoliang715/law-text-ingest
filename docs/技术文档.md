# 技术文档 · law-text-ingest

**版本** 1.0.0 ｜ **定位** 法律文本摄入工作流（不属任何流水线，独立使用）｜ **运行时依赖** Python 3.9+，标准库

## 1. 定位

把法律 PDF 转成知识库页面，并留下可复核的取证链。与普通摄入技能的核心差别：**它假设"正确"是客观可判的**，因此自检不能抽查，必须逐条。

## 2. 输入契约

| 项 | 要求 |
|---|---|
| 输入形态 | 文本型 PDF（扫描件需先 OCR，不在本技能范围） |
| 必需信息 | 法律名称、版本 / 修正案状态、通过机关与施行日期 |
| 可选信息 | 编章节结构、条文总数（用于核对完整性） |

信息缺失时的处置顺序：先查立法机关动态 → 查不到则标注「未确认」并写明检索范围与时间，**不得用转载文补**。

## 3. 输出契约

- 页面结构：法律名称 / 版本与时效 / 编章节层级 / 条文（按条号排序）/ 出处与核对留痕
- **必需字段**：`修正截止`（或等价表述）、`对应原始资料`、`核对范围`
- **必需留痕**：逐条核对记录（核对了哪几条、依据原文哪个位置）

## 4. 判定逻辑（`scripts/law_helper.py`）

脚本负责段落定位与结构抽取，不负责判断法义。主要能力：

1. 从 PDF 文本中定位「第X编 / 第X章 / 第X节 / 第X条」层级
2. 按条号切分正文，输出可直接落页的结构化片段
3. 辅助核对：给定条号，回原文取该条文本

**它不做的事**：不判断条号是否真实存在（PDF 本身错则照录）、不推断缺失条文、不做跨法条引用解析。

### 已知限制

| 限制 | 后果 | 缓解 |
|---|---|---|
| 依赖 PDF 文本层质量 | 换行错位会让条号识别偏移 | 抽取后人工抽查前 10 条与末 10 条 |
| 不识别竖排 / 表格内条文 | 附表、修正对照表会漏 | 这类内容单独人工处理 |
| 不校验版本新旧 | 抽得对但可能抽的是旧版 | 时效核查必须在抽取前完成 |

## 5. 能力边界

**能做**：结构抽取、条号定位、逐条核对辅助、时效性检查的取证流程。

**不能做**：法条解释、适用判断、判例检索、OCR、跨法条推理。

**边界判据**：凡是需要"法律判断"的，一律不属本技能；只做"文本搬运 + 可复核"。

## 6. 设计取舍

| 选择 | 为什么不选另一条路 |
|---|---|
| 结构用脚本抽，不用肉眼 | 条号是坐标，人眼数层级必然漏；脚本至少错得可复现、可定位 |
| 逐条核对而非抽查 | 法律文本里一条错足以推翻整篇结论，抽查兜不住 |
| 否定结论必须写检索范围 | 「没查到」与「不存在」是两件事，混用会产出假结论 |
| 汇编版冲突照录 | 替用户做取舍等于替用户下法律判断，越界 |

## 7. 优缺点

**优点**：零依赖；结构抽取可复现；核对留痕可被第三方复核；把"版本"这个最易错项前置成门禁。

**缺点与缓解**

| 缺点 | 影响 | 缓解 |
|---|---|---|
| 完全依赖 PDF 质量 | 扫描件无法直接用 | 前置 OCR 步骤，不在本技能内 |
| 无自动化正确性校验 | 抽取对但内容可能被篡改 | 逐条核对留痕，靠复核而非自动判定 |
| 只覆盖中国法律文本格式 | 域外法典层级不同 | 明确不适用，别硬套 |

## 8. 失败模式与处置

| 现象 | 根因 | 处置 |
|---|---|---|
| 条号整体偏移 | PDF 文本层换行/分栏错乱 | 换 PDF 来源；或按页人工校正起止条号 |
| 编章节层级断裂 | 原文用编号而非"第X章"字样 | 人工补层级，并在留痕中注明 |
| 抽查发现引文与原文不符 | 复制时跨页截断 | 定点重取该条，不要整篇重抽 |

## 9. 与其他技能的关系

**无依赖**。它不调用任何流水线技能，也不被调用。可与任意知识库工具链搭配，只需最终落成 Markdown。
