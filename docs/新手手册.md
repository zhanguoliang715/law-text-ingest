# 技能说明 · law-text-ingest（法律 PDF 入库）

## 一句话

把法律 PDF（法典、单行法、修正案、司法解释）收进知识库，**保证条号和版本不出错**。

## 什么时候用

- 手上有一份法律文本 PDF，要收进 Obsidian 或任何 Markdown 知识库；
- 想知道手上这一版是不是最新的；
- 要把一部法按编 / 章 / 节拆成可检索的页面。

**不适用**：判例、论文、普法文章。那些属描述性资料，用普通摄入流程即可。

## 为什么法律资料要单独一个技能

同样是"读一份 PDF 写摘要"，法律资料和文章的要求完全不同：

| | 文章 / 教程 | 法律文本 |
|---|---|---|
| 事实对错 | 无法判定，只能标"作者观点" | **可判定**——条文原文就是唯一答案 |
| 条号 | 不适用 | **是定位坐标，错一位全错** |
| 自检强度 | 抽查引文 | **逐条回原文核对** |

所以这个技能的三条主线都是围绕"可验证"来的：时效性核查、编章结构用脚本提取、逐条回原文留痕。

## 它怎么做

1. **判版本时效**：先确认这份文本是哪一版，有没有更新的修正案。判"最新"只认立法机关动态与主席令，不用转载全文倒推。
2. **脚本提取编章结构**：编 / 章 / 节 / 条的位置不靠肉眼数，用 `scripts/law_helper.py` 从 PDF 文本里抽，避免手工抄错层级。
3. **逐条核对**：页面里每条引文都要能指回原文位置；找不到出处的标"原文未提供"，不猜。
4. **留痕**：核对了哪几条、依据原文哪个位置，写进报告。没有留痕视为没做。

## 边界

- **不替你判断法条含义**，只保证"抄得对、版本对"。
- **不做跨法条推理**。体系解释、竞合判断属法律专业工作。
- 碰到**汇编版同条号两套刑档**这类情况，照录不取舍，把冲突标出来——取舍是人的事。
- 只处理**文本型 PDF**。扫描件需要先 OCR，本技能不含 OCR。

## 怎么验

```bash
python skills/law-text-ingest/scripts/law_helper.py --help
```

具体子命令以 `SKILL.md` 为准。判断完成的标准不是"脚本跑通了"，而是**抽出的编章结构与原文逐条对得上**——这一步必须人工过一遍。

## 最常见的三个错

1. **用转载文判断"最新"**。转载站常滞后半年，看到的全文可能是旧版。
2. **条号手抄**。第 264 条写成第 246 条，整篇结论作废。
3. **把"没有找到修正案"当成"没有修正案"**。否定结论只能覆盖你实际查过的范围，查不到要写清"取到几条 / 总量多少"。
